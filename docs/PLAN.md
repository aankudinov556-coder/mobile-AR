## 1. Ошибка в Android-приложении: вместо запуска приложения в чате появляется JSON

**Как воспроизводится:** просишь «открой Telegram» (или другое приложение). В чате появляется JSON вида
`{"name": "open_app", "arguments": {"name": "Telegram"}}`, приложение не открывается.

**Диагноз (по коду, на телефоне ещё не проверено):**
- Сам запуск в `Vera.Mobile/Platform/PhoneTools.cs` → `OpenApp` устроен правильно:
  - в манифесте объявлена видимость лаунчер-приложений (`<queries>` с `MAIN`/`LAUNCHER`);
  - у интента запуска стоит `NewTask`, запуск идёт через текущую Activity.
- Если в чате виден сырой JSON, инструмент **не вызывался**. Модель написала вызов обычным текстом.
  Так делают модели без поддержки function calling — например, часть бесплатных моделей OpenRouter (`…:free`).
  Бывает и так, что провайдер отдаёт вызов в `content`, а не в `tool_calls`.
- Ядро исполняет только настоящие `tool_calls` (`OpenAICompatProvider.StepAsync`), поэтому текстовый JSON просто показывается.

**Уточнено:** провайдер — **OpenRouter**. Какая модель, пока не известно, скриншот JSON всё ещё пригодится.
Это подтверждает версию о причине: у OpenRouter много моделей без поддержки вызова инструментов.

**Правки:**
1. **Резервный разбор вызова из текста.**
   - Если в тексте ответа есть объект с `name` ∈ известным инструментам и `arguments`/`parameters` (а также блоки
     ```` ```json ```` и `<tool_call>…</tool_call>`), превращать его в настоящий вызов инструмента и убирать JSON из ответа.
   - Покрыть тестом в `Vera.Core.Tests`.
2. **Выбор модели.**
   - В списке моделей OpenRouter помечать модели без `tools` и предупреждать при выборе.
   - Если модель отвечает 400 «tools not supported», показывать понятную ошибку с советом сменить модель.
3. **Диагностика.** Добавить переключатель «Журнал запросов» в настройках: сырые ответы последних ходов пишутся в файл.
   Пригодится для таких случаев на телефоне.
4. **Сам `open_app` на Android:**
   - если приложение не найдено, показывать чип «📱 не нашла» с кнопкой «выбрать из списка»;
   - логировать исключения `StartActivity`, а не только показывать toast.

## 2. Новая сидячая поза — «сидит на полу» (как на примере)

На примере чиби сидит на полу, поджав ноги под себя (вариза). Ладошки на коленях, под ней мягкая тень, вокруг искорки.
Позу рисуем **для Веры её собственным спрайтом** — с примера берём только идею позы.

**Спрайт** (`tools/gen_sprite.py`):
- Новые слои `floor_<pose>`:
  - юбка раскрыта по полу, колени вперёд, голени поджаты под себя;
  - руки: `idle` — ладони на коленях, `giggle` — рука у рта, `wave` — машет.
- Голова и лицо — те же слои глаз, рта и румянца, поэтому вся мимика работает и сидя.
- Тень-эллипс на полу, отдельным слоем или средствами UI.
- Искорки ✦ розового цвета — эффект в UI, всплывают изредка.
- Опционально — слой «предмет во рту/в руках» (палочка-печенька, чупа-чупс, кружка): мелкая деталь характера.

**Ядро** (`Vera.Core/Sprites/VeraSprite.cs`):
- Параметр позы: `stand` | `bar` (сидит на панели — текущая мобильная) | `floor`.
- `Compose(...)` выбирает `base_*` / `sit_*` + `legs_sit_*` / `floor_*`.
- Тесты на порядок слоёв.

**ПК** (`Vera.Desktop/Pet`):
- Через N минут простоя Вера садится на пол (анимация «присела»), при наведении или клике встаёт.
- Опция в настройках «Садиться, когда скучно».

**Android** (`Vera.Mobile/Views/VeraView.cs`):
- На пустом экране чата (нет сообщений) Вера сидит «на полу» по центру.
- Когда начинается диалог, перепрыгивает на панель ввода.

## 3. Персонаж «J» из Murder Drones

Готового персонажа J из Murder Drones не рисуем — это чужой персонаж.

**Альтернатива — оригинальный скин «Вера-дрон»:** робо-девочка в похожем жанре, но со своим дизайном.
- Визор-экран вместо глаз, на нём рисуются эмоции: ^^, >_<, ?!.
- Металлические «ушки»-антенны, хвост-кабель с розовым сердечком-штекером на конце, куртка-оверсайз с неоновой окантовкой.
- Своя палитра: графит + розовый неон, без чужих цветовых схем и символики.
- Технически это отдельный набор слоёв с тем же форматом и той же схемой эмоций.
  В настройках выбор: **Вера / Вера-дрон**, в коде — `assets/<skin>/`.

---

**Концепт v2 (`tools/concepts/gen_drone.py`, `docs/concepts/drone_*`):** полностью нечеловеческая робо-девочка
в стиле «крупный пиксель + толстый контур + обводка-стикер»:
- округлый шлем-голова, вместо лица экран со светодиодными эмоциями;
- антенны с огоньками, белая броня, графитовые куртка-панели;
- розовое ядро-сердце на груди, металлические руки и ноги на шарнирах;
- хвост-кабель с сердечком-штекером, без крыльев.

Дизайн свой, черты чужих персонажей (силуэт, цвета, форма, жало) не используются.
Позы: стоит, машет, «хи-хи», думает, сидит на полу. Эмоции на экране: 9 штук.

## 4. Технический бэклог (из отчётов по ПК- и Android-версиям)

- **TTS:** передавать скорость голоса в OpenAI TTS (`SpeedRatio` из `Tts.Rate`) вместо растяжения mp3 на ПК.
- **`VoiceRecorder`:** после успешной команды возвращать состояние `Off`/`Wake` самому, не оставлять это платформе.
- **`VeraAgent`:**
  - отдельный тип исключения «занято» (или метод `TrySend`), чтобы не сравнивать текст ошибки;
  - описать в `API.md`, что `Pet.X/Y` на ПК хранятся в физических пикселях.
- **Android:** постоянный ключ подписи APK через секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
  `ANDROID_KEY_ALIAS`. Без них обновление ставится только после удаления старой версии.
- **Релиз:** добавить текст описания релиза v2.0.0 (сейчас там только файлы).
- **Проверить на устройствах:**
  - Android: клавиатура и отступы, касания мимо Веры к кнопкам под ней, липсинк на разных прошивках;
  - Windows: toast-уведомления, прозрачное окно, скриншот, системный голос.
